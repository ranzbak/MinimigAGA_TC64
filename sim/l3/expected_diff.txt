# sim/l3/expected_diff.txt: the only allowed differences between the RV
# and the 832 traces of one L3 scenario (README "Differential"; syntax in
# sim/host_bridge/spitrace.py's help).  Every rule has a '#' line above it
# naming its source; a rule no scenario uses is removed (run.sh diff
# --unused-rules).  Not needed in boot, so not here: the version strings
# (both builds print the same L3_DATE; "-RV" is only in MM_VERSTRING, which
# no output shows) and the failure-path timeouts (boot takes none).

# exec-3 hand-over item 3 (doc/osd-riscv-exec-3.md "What Phase 4
# consumes"): the firmware file name, size and sectors.  The RV boot ROM
# loads RV32OSDA.BIN, the 832's 832OSDAD.BIN (other sizes); the boot ROM
# prints one '0' per sector it loads
SDFILE RV32OSDA.BIN FIRMWARE
SDFILE 832OSDAD.BIN FIRMWARE
SUBST uart file\x20"(RV32OSDABIN|832OSDADBIN)"\x20found\\r0+ file "FIRMWARE" found\\r0..

# exec-3 hand-over item 3: the config file names.  The RV firmware reads
# MINMGAR.CFG (little-endian), the 832's MINMGAA.CFG (big-endian; the same
# fields, sim/l3/card)
SDFILE MINMGAR.CFG CONFIG
SDFILE MINMGAA.CFG CONFIG
SUBST uart file\x20"MINMGA[RA]\x20CFG"\x20found file "MINMGA? CFG" found

# fw/ctrl_rv/test/gold/fmt_diff_expected.txt line 275 (case 879 P ZERO:
# 'partition type: 0x%02X (' U(0)): the 832's printf prints 0x0, the RV's 0x00
SUBST uart partition\x20type:\x200x0\x20\( partition type: 0x00 (

# Task 7 finding (findings/osd-riscv/phase4.md "Findings for Paul", run
# p4t7probe): an 832-only firmware defect, not RV parity.  The 832 build
# corrupts ColdBoot's `override` (L3PROBE1 key=0 override=0, L3PROBE2
# key=0 override=6F6E2036 across sprintf("Got key: %x\n") and the empty
# BootPrint(); lib832 / vbcc832 sprintf suspected), so it prints
# "Overriding screenmode." and runs ApplyConfiguration(0,0) a second time
# with no key held; the RV (right per the source) does neither.  The block
# ends at the "##End result : 0" line that ApplyConfiguration prints
DROPBLOCK uart ^Overriding\x20screenmode\.$ ^##End\x20result\x20:\x200$

# fw/ctrl_rv/arch/irq.c:22 (SetIntHandler: IRQ_MASK = 0 for a legacy
# handler) and exec-1's memory map (the RV interrupt controller at
# 0xFFFFFF30..3C): an RV-only register, the 832 has none
DROP hw ^ffff34\x20

# fw/ctrl_rv/test/gold/fmt_diff_expected.txt lines 37-44 (cases 152-155
# PREC: 'Inserting floppy: "%.11s"\r'): lib832's printf has no precision,
# the 832 prints "11s", the RV the 8.3 name (menu.c InsertFloppy, a file
# without a long name; fdd_rd: "TEST    ADF", runs p4t13 / p4t13c)
SUBST uart Inserting\x20floppy:\x20"(11s|[^"]{11})" Inserting floppy: "%.11s"

# fw/ctrl_rv/test/gold/fmt_diff_expected.txt lines 45-52 (cases 156-159
# PREC: 'file: "%.8s.%.3s"\r'): lib832's printf has no precision, the 832
# prints "8s.3s", the RV the hardfile's 8.3 name (hdd.c OpenHardfile; hdd:
# "RDB     .HDF" and "SYNTH   .HDF", runs p4t15 / p4t15c)
SUBST uart file:\x20"(8s\.3s|[^"]{8}\.[^"]{3})" file: "%.8s.%.3s"

# Task 15, runs p4t15 / p4t15c (hdd): OpenHardfile() prints how long
# BuildHardfileIndex() took, in TIMER counts (one count = 256 clk_28 at
# TICKDIV 1), so the number follows the CPU's speed: RV 289 / 539, 832
# 621 / 1174 for RDB.HDF / SYNTH.HDF.  It is only printed (hdd.c:932 RV,
# hdd.c:910 832): no bound, no decision depends on it
SUBST uart Hardfile\x20indexed\x20in\x20[0-9]+\x20ms Hardfile indexed in <TIMER counts> ms

# fw/ctrl_rv/test/gold/fmt_diff_expected.txt lines 144-145 (cases 565, 568
# SIGNUART: 'Offset: %ld'): lib832's sprintf puts a negative number's '-'
# on the UART and the digits alone into the buffer.  ApplyConfiguration's
# boot-screen line "Offset: %ld" of hdf[1].offset (config.c 832 :491, RV
# :561) is -32 for SYNTH.HDF (HDF_SYNTHRDB), so the 832's UART gets one '-'
# (hdd: in front of the next printf, after "Hardfile indexed ... ms\r";
# runs p4t15 / p4t15c).  After the rule above
SUBST uart (Hardfile\x20indexed\x20in\x20<TIMER\x20counts>\x20ms\\r)-(file\x20") \1\2

# Task 13 ruling (3), runs p4t13 / p4t13c (fdd_rd): drivesounds_render()
# writes AUDIO = AUDIOF_ENA on every main-loop pass while the motor sound
# plays (drivesounds.playing is never set: findings/osd-riscv/phase4.md
# "Shared defects"), so the count of these no-op rewrites follows the CPU's
# speed (12,083 / 4,569).  A write with a changed value stays
DEDUP hw ^ffffb0$

# Task 13 ruling (5), runs p4t13 / p4t13c: the I2C (ffff60), keyboard
# (ffff90) and ffffa0 write group that a TIMER-driven call makes in the
# main loop lands among other frames on each CPU (spi.txt line 82,967 /
# 31,794); compared as its own ordered sub-stream.  After the DROPBLOCK
# above, so the 832-only ApplyConfiguration pass stays dropped
FLOAT hw ^ffff(60|90|a0)$

# Task 13 ruling (6), runs p4t13 / p4t13c: the audio ring holds the drive
# sounds rendered per TIMER count (drivesounds_render(TIMER), pickstep's
# TIMER&3), timing-dependent; scenario cdda checks its ring against
# TEST.BIN with l3check.py on each CPU (Task 17)
DROP hw ^MEM\x20audio_ring\x20
