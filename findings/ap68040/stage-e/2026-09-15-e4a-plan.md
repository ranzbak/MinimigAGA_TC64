# Stage E4a — Remove What Is Already Dead: Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Delete the memory-path logic that decisions and hardware tests have already made dead, so the AP68040 core is smaller to read and debug, without changing its behaviour.

**Architecture:** Six removals, one commit each, in order of increasing reach: debug instrumentation → two tied-off controller options → settled build switches → the constant-off 32-bit chipset cycle path → the TG68K CPU branch. Each removal is proven behaviour-neutral by the bench legs that exercise what it touches. The full suite runs once at the end, then one build and one hardware test. Nothing in the 32→16→32 conversions changes here; that is E2/E3.

**Tech Stack:** VHDL-93, Verilog/SystemVerilog (xsim), iverilog (`sim/sdram_coherency`), Vivado 2023.2 Tcl, XDC.

**Spec:** [2026-09-15-stage-e-design.md](2026-09-15-stage-e-design.md) — §3 decisions 2 (AP68040 only) and 3 (complexity budget), §5 E4. Paul, 2026-09-15: "Do E4a first, I agree" (E4a after E1's bench is trustworthy, before E2).
