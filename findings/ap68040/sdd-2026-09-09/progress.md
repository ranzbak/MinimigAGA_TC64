## Global constraints (handed to every reviewer)
1. TG68K build stays behaviour-identical: plain ./run.sh (sim/ddr3_cpu) and sim/autoconfig unchanged.
2. lib/AP68040 stays pristine apart from the deliberate x3 overlay commit; rtl/cpu040/dpram.v is compiled INSTEAD of the submodule's primitive (tools/test_ap040.sh).
3. sim/ddr3_cpu variants run ONE AT A TIME; mutants --lwmutant and --mmumutant MUST fail on the summary line; never edit run.sh while a run is in flight; the bench does not compile sdram_ctrl -- it models the enable cadence itself, so a cadence change in RTL must be mirrored in the tb or it tests nothing.
4. The AP040 issues independent 16-bit word cycles: longword_pair = 0, cpustate(6) never set for the AP040 (bench asserts it).
5. The walker borrows the CPU bus; a line fill and a descriptor read must be ordered, never interleaved. clkena must stay alive while the walker owns the bus.
6. Coherency: cpu_cache_new is write-through and snoops chipset DMA into board 3; a line read that bypasses it is safe only while writes keep going through it (findings/ddr3/design.md).
7. cpu.xdc kernel/wrapper/memory multicycle sets are by instance path; anything renamed must be re-queried in the netlist; free-running (non-ce) registers must be excluded from the kernel set.
8. Sign-off for a build: kernel island WNS >= 0 under -start 4; SDRAM read path clk_gen_sdram -> clk_114 no worse than -0.544 ns; DDR3 CDC exceptions unchanged in report_exceptions.
9. Do not stage or commit Paul's pre-existing uncommitted edits (fw/ctrl_832/version.h, sim/hostcpu-i2c-bridge/*.wcfg, tools/vivado/ila_fastram_check.py) or untracked scratch files.
10. Vivado 2023.2: LD_LIBRARY_PATH libtinfo.so.5 shim, never -stack; call /opt/Xilinx/Vivado/2023.2/bin/vivado directly.
